## 三、Godot 接入

```gdscript
var scene = load("res://assets/models/chars/ZhouXiulan_Anim.glb").instantiate()
add_child(scene)

# 找到 AnimationPlayer（通常在 glb 根节点下）
var ap: AnimationPlayer = scene.find_child("AnimationPlayer", true, false)
ap.play("Idle")
```

动作名就是上表里的 `Idle` / `Walk` / `SitDown` 等，直接用。

**注意**：
- 骨架根节点名是 `target_character`，骨骼命名 `mixamorig:*`（标准 Mixamo）
- 坐姿动作（`SitDown` / `SitIdle`）假定椅面高度约 **0.45 m**；如果椅子高度不同，需要调节点 Y 偏移
- `LookDown` 起点在站姿，若要在坐姿下低头，需要与 `SitIdle` 做 blend

## 六、踩过的坑（重要）

### 坑 1：Meshy 静态网格与动画网格顶点顺序不同
- 静态版 17,211 顶点，动画版 17,221，**差 10 个**
- 归一化后位置**完全重合**（最近邻距离 0），说明是同一模型但**顶点顺序被打乱**
- **不能按索引搬权重**，必须用 `Data Transfer` 的最近邻映射

### 坑 2：两个网格坐标系不同
- 静态版**居中于原点**（z = -0.95 ~ 0.94）
- 动画版**脚底在 z=0**（z = 0 ~ 1.7）
- **如果直接做权重转移会全错**：第一次失败时头顶权重全跑到腿骨上，头直接消失
- 修法：**先把静态网格的坐标对齐到动画网格**（缩放 + 对齐脚底），再转移

### 坑 3：Mixamo fbx 的 rest pose 不是 T-pose 语义
- 导入 Blender 后 armature 被旋转 90°，骨骼局部轴定义与 Meshy 完全不同
- 左臂：Mixamo 沿 `X` 轴、Meshy 沿 `Y` 轴
- **直接拷旋转值 → 全身扭曲**（试了 delta、桥接矩阵、约束烘焙，全部失败）
- **正确做法（最终方案）**：
  ```
  src_rest_world = 源骨架清空姿态后的世界朝向（T-pose）
  src_pose_world = 源骨架每帧世界朝向
  delta          = src_pose_world * src_rest_world^-1
  tgt_pose_world = delta * tgt_rest_world
  逐帧、从根到叶用 pb.matrix 设置
  ```
  这个方案同时吸收了「源 T-pose ↔ 目标 A-pose」的差异

### 坑 4：Meshy 自带动画的骨架动作手臂是 A-pose 张开的
- Meshy 的 Idle / Walk 动作，手臂停在 A-pose 角度不动
- 修法：算出 Mixamo Idle 的**标准站姿手臂**（10 根骨骼），替换 Meshy 动作里的手臂 fcurve

### 坑 5：GLB 导出动作的两种模式
- `ACTIONS` 模式：只导出**已分配给对象**的 action（会漏）
- `NLA_TRACKS` 模式：每个 action 挂一个 NLA track 再导出（可靠）
- 用 `NLA_TRACKS` + `export_nla_strips=True`

## 七、已知不足

1. **`Walk` 的手部略僵硬**：因为手臂用了固定值覆盖，手指不会随步伐摆动
2. **`SitIdle` 手的位置**：Mixamo 的坐姿手部本来是放在大腿上的，重定向后略有偏移
3. **`Male_Sitting_Pose.fbx` 已排除**（无效文件，只有 2 帧）
4. **阿七的 biped 包是「一个文件一个动作」**：构建时需要用 `extra_anims` 从多个文件合并（已在 `build_final.py` 里配好）
5. **孩子（秀兰）的动作速度**：Walk/Run 已按 1.25 倍加速，但 Mixamo 动作本身是成人节奏，重定向后腿部有时略显夸张
