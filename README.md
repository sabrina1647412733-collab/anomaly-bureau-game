## 导出 Web 版（重要，别踩这个坑）

Web 导出只能走 Compatibility（GLES3）渲染器，Godot 在 Web 平台会自动使用它，`project.godot` 不需要额外写 `renderer` 行。

兼容渲染器默认**一帧只渲染 32 盏灯**（`rendering/limits/opengl/max_renderable_lights`）。本作场景有 106 盏，
所以 `project.godot` 已把它提到 **128**；以后场景灯数超过 128 时还要继续提高，否则会重新出现
「某些角度突然没灯」。详见第 61 节。

导出模板已装在 `%APPDATA%\Godot\export_templates\4.7.2.stable`（含 `web_nothreads_release.zip`）。推荐直接用脚本：

```powershell
powershell -File F:\诡异事务局\_handover\scripts\export_web.ps1 -Root "F:\诡异事务局"
```

脚本会导出到 `deploy\game\` 并把浏览器标题统一成《诡异事务局 · 第一季「补丁」》。
手动导出命令（与脚本等价，但不改标题）：

```powershell
$G = "C:\Users\Sabrina\AppData\Local\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe\Godot_v4.7.2-stable_win64.exe"
& $G --headless --path "F:\诡异事务局\岚桥站0017-Godot" `
     --export-release "Web" "F:\诡异事务局\deploy\game\index.html"
```

产物是 `deploy\game\` 下的 `index.html / index.js / index.wasm / index.pck`，再由工作区根目录打包成 `0017-网页版.zip`。


## 逐件精修与自查（开发用）

站体是一件一件做的，每件都走同一套循环：**生成 → 载入自检 → 0 错误 → 截图对比 → 提交**。

```powershell
$G = "C:\Users\Sabrina\AppData\Local\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe\Godot_v4.7.2-stable_win64_console.exe"
# 1) 载入自检：必须 exit 0 且没有 SCRIPT ERROR（末尾那条 ObjectDB 泄漏警告无害）
& $G --headless --path . --quit-after 90

# 2) 六个固定机位对比图 → _预览/look/<tag>_NN_名字.png
& $G --path . --script res://scripts/tests/look_shots.gd -- <tag>

# 3) 单个构件的定点近景 → _预览/look/<名>.png
& $G --path . --script res://scripts/tests/closeup.gd -- <名> <x> <y> <z> <yaw> <pitch> [fov]
```

**注意**：截图**不能**加 `--headless` —— 无头模式下 `root.get_texture()` 拿不到帧，脚本会一直挂着。

没有显示器时用工作区 `_tools/` 里的三个小工具把画面「读」出来（Pillow）：

| 工具 | 用途 |
|---|---|
| `python _tools/asc.py <png> [宽] [高] [crop] [gamma]` | 把截图降采样成字符画（默认 gamma 0.62 提亮，暗场景也看得清结构） |
| `python _tools/probe.py <png> <cx> <cy> <cz> <yaw> <pitch> <fov> "标签:x,y,z" …` | 把世界点投影到像素并报出该处的 RGB / 亮度，用来核对「这个构件在画面里到底有没有读出来」 |
| `python _tools/aim.py <cx> <cy> <cz> <tx> <ty> <tz> [目标高度]` | 由机位和目标点反算 yaw / pitch / 该用多大 fov |

## 逐件精修记录

### 1 · 五号继电器柜（7.40 m · 信号室 z 24.55–31.95）

**原状**：柜体、柜门、玻璃窗、五排继电器、端子排、铭牌、电缆槽的几何都在，但**一条都读不出来**——
信号室只有一盏顶灯，柜门面亮度只有 15/255；玻璃用的是不透明着色器，把柜内**整片挡死**（端子排与继电器排根本看不见，
之前量到的「端子排 29」其实是柜门自己的颜色）；铰链、把手、指示灯亮度 9–32。

**改动**：

- 新增 `shaders/glass_panel.gdshader`（在 `surface.gdshader` 上加 `ALPHA` + 掠射角 Fresnel），
  `station.gd` 的 `_mat()` 按材质里有没有 `alpha` 键选着色器，`glass` 材质设为 `alpha 0.34`。
  三处玻璃（继电器柜观察窗、售货机橱窗、广播台观察窗）一并变成真半透明。
- `level.gd` 的 `relay_cabinet()` 重做：踢脚 → 圆角柜体（倒角 0.045，整柜一个碰撞盒）→ 门框四压条 →
  玻璃观察窗（上腔五排继电器 / 下腔 14 组端子排，中间一条分界横档）→ 北端三副圆柱铰链 + 南端把手与锁 →
  铭牌（带四颗螺钉）+ 两盏柜顶指示灯（琥珀 / 红，各带灯罩底座）→ 底部电缆槽（槽体 + 两根电缆 + 六副支架）→ 柜内三盏小灯。
  第 5 排继电器用红色指示灯，对得上「五号继电器反馈慢半拍」的剧情。
- 信号室加第二盏顶灯：一盏灯照不到 7.4 m 的南半段。

### 9 · 坐下视角穿模修正

**报障**：坐下时视角穿模。

**根因**（两条，都实测过）：

1. `player.gd` 的 `_update_body()` 在「坐着」分支里**无条件把玩家身体显示出来**（`body.visible = true`），
   而第一人称坐姿眼高只有 1.22 m，正好落在自己**头部方块内部**（当时 y 1.045–1.275）——
   相机卡在自己脑袋里，所以坐着看哪儿都像穿模。

- 柜内五排的排号「1..5」字号 0.115（字高 0.25 m），而排距只有 0.17 m —— 数字比排还高。

根因在 `station.gd::plaque()`：字高写死成 `h * 0.58 * 2.2 = 1.28h`，**只跟牌高有关、跟牌宽和字数无关**，

    var sz := minf(h * 0.62, w * 0.92 / (float(maxi(text.length(), 1)) * 1.15)) / 2.2

即「字高不超过牌高的 62%」且「所有字加起来不超过牌宽的 92%」（1.15 是字间距余量）。
11 块牌子全部自查一遍：5 号铭牌 0.242→0.115、售货机 0.204→0.099、环线大字 0.536→0.239…全都在牌子里面了。

### 37 · 走路时躯干上下起伏 1.2cm

改法（`player.gd::_update_body`，在 `walk_phase` 递进之后一行）：

    body.position.y = sin(walk_phase * 2.0) * 0.012 * clampf(planar / SPEED_WALK, 0.0, 1.2)

- `walk_phase * 2.0`：两步一个起伏周期（左右各一步）。

### 48 · Web 性能：为什么卡，以及 Web 低画质档

用户反馈网页卡。项目自带 `webverify`（Edge headless + SwiftShader）实测：
- **基线：2 FPS / 519 draw calls。**
- GPU：`ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device ...), SwiftShader driver)` —— **软件 WebGL**，没有硬件加速。
- 优化后：**3–4 FPS / 150 draw calls**（仍是 SwiftShader）。真实硬件 GPU 会高很多。
- 另一个干扰：之前后台隐藏的 Godot 游戏实例累计跑了 **1949 s CPU**，会和浏览器抢 CPU/GPU，已停止。

Web 低画质档（只在 `OS.has_feature("web")` 生效）：
- 关泛光、关 SSAO、关 MSAA，3D 渲染缩放 **0.65**，`Engine.max_fps = 60`。
- 站内灯：隐藏 energy **< 1.3** 的装饰灯（75 → 22 盏有效主光），主光范围收紧、能量补偿。
- 列车灯：`lights_on(false)` 时直接 `visible = false`（不再用 0.02 能量常驻）。
- 手电：Web 端关闭 shadow map。
- HUD：地图重绘 15 Hz、游戏数据更新 10 Hz；**菜单打开时整个 HUD 隐藏**。
- Label3D：Web 端 22 m 可见距离，远端标牌不参与渲染。
- GPU 检测：`JavaScriptBridge` 读取 `WEBGL_debug_renderer_info`；检测到 SwiftShader/软件渲染时，菜单直接显示警告。

### 61 · 网页版「某些角度突然没灯」：Compatibility 灯上限 32

现象（玩家反馈）：

- 网页版里，灯光会随视角/位置变化突然整片消失；序章出租屋和车站都遇到过，走近或转个方向又亮回来。

根因：

- Web 导出走 Compatibility（GLES3）渲染器。Godot 默认 `rendering/limits/opengl/max_renderable_lights = 32`，
  即**一帧最多只渲染 32 盏灯**；本作场景共 **106 盏**，超出的灯被静默丢弃，不会报错。
- 每帧保留哪 32 盏会随可见灯列表变化，所以表现成「某些角度没灯」，而不是固定区域黑。
- 桌面端默认 Forward+ 不受这个上限影响，因此只出现在网页版（以及手动用 `--rendering-driver opengl3` 时）。

修复：

- `project.godot` 写入 `limits/opengl/max_renderable_lights=128`，覆盖全部 106 盏灯；单对象上限保持默认 8 盏，
  片元着色器开销不变。
- `game.gd` 网页版启动日志新增 `[WEB] light_limits renderable=... per_object=...`，以后一眼能看出是否又踩回去。

实测（同一机位、网页版 WebGL2 + RTX 3070）：

| 场景 | 修复前（32） | 修复后（128） |
|---|---|---|
| 车站 · 站台中段平均亮度 | 10.78 / 255 | 44.71 / 255 |
| 车站 · 关灯后的应急灯 | 10.77 / 255 | 19.21 / 255 |
| 序章出租屋（门口机位） | 78.07 / 255 | 78.06 / 255（本就够用） |
| 帧率 | 60 FPS | 58–60 FPS |

### 尺寸约定（踩过坑，写死在这里）

`laundry_art.gd` 里两个建盒子函数**都是全尺寸**语义：

| 函数 | size 含义 | 说明 |
|---|---|---|
| `a.box(pos, size, ...)` | 全尺寸 | `BoxMesh.size` |
| `a.bev(pos, size, ...)` | 全尺寸 | 内部 `CharBody.bev_box(size, b)` |
| `a.col(pos, size, ...)` | 全尺寸 | 碰撞盒 |

而 **Blender 脚本里 `bevel_box(size=...)` 的 size 是半边长**（`create_cube(size=2.0)` 再乘）。
两边混用会直接导致「机身只有一半大、门圈和面板相对过大，整台机器像躺在地上」。
今晚在 5F 503 的玩具洗衣机上踩了两次，记在这里。
