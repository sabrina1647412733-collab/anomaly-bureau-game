# 主街样板制作约定

- 场景结构真值：原town-layout及现有地标覆盖、shop_recesses；目标图是已认可的美术方向，不用于重写道路与门洞尺寸。
- 相机固定：镇内feet(150,.10,124.1)，target(165,.5,126.5)，eye1.66m/FOV74/1600×900。其他侧机位用于揭露遮挡和穿模，不能代替主机位的构图验收。
- 原接受基线：Git `0caace6`，`01_before_godot.png`原样复制。第一轮实机保留于F盘验收/20261023_主街样板落地/实机_v1，不覆盖为“已完成”。
- 工序：现有布局→Blender后台几何批次/道具→GLB→Godot材质与组装→真实玩家视角→通行/天气/存档回归。不修改桌面打开的Blender场景、不安装桥接器、不另建替代项目。
- 坐标：生成器使用Godot x/up/z米制，提交到Blender网格时一次转换(x,-z,y)，glTF Y-up导出一次还原；道具GLB已含镇内世界坐标，运行不再叠加建筑front变换。
- `wicker/enamel/enamel_flower`必须保留原生PBR并在Godot显式启用顶点色。仅验证GLB存在COLOR_0不足以证明实机颜色正确。
- 防滑钢板、涂漆空调和浅灰雨管是不同材质用途；不允许只因同为金属就全套深色花纹钢板。
- 所有近景硬物体使用同一导出manifest的碰撞；保护门前、道路与原有剧情入口。角色暂停，不以新增人形补画面。
- 桌面输出、源文件、截图、草稿都存F盘。图片生成器返回的本轮PNG已移入本目录或F盘验收目录，C盘不保留本轮生成PNG。

## 第一轮复查与修正

使用quality-refinement-autoloop方法保留证据并逐项诊断。现有导出、材质、Godot与机位验收方法足以修复，本轮无需增加或改写全局技能。

| 证据 | 诊断 | 定向修复 |
|---|---|---|
| 侧机位藤椅/盆纯白 | 原生导入未启用顶点色 | 运行时复制材质并启用vertex_color_use_as_albedo |
| 电表挡在首层窗上 | 新增窗户后仍使用旧固定电表横坐标 | 电表改到外侧实体墙垛，避开窗框 |
| 主机位看不到椅盆 | 门的局部左右与屏幕左右不同 | 使用同门另一侧，并重新检测道路/门口净空 |
| 空调雨管呈深黑 | 防滑钢板贴图及金属度不符合表面用途 | 单独painted_metal/galvanized浅色PBR |
| 连续脏灰泥缺少剥落形态 | 原grey_plaster只有细碎脏点 | 仅样板部分立面使用hero_plaster，保留完整灰泥变化 |
| 路面和路缘过平整 | 大平面细纹法线不足以表现边界 | 局部沥青修补、独立边沟石、闭合抬高铺装的侧边 |

最终实际结果见工程根目录`20261023_主街样板实机精修验收.md`。04/05/06三张完成图已从最终Godot截图原样复制并核对SHA-256。

## 最终复查

- 搪瓷盆花纹扇面绕序原本向内，蓝边原本埋入白色卷口；定向修正面朝向与外露顶缘后，实机红花和蓝边均已显示。不能只检查导出面数就接受道具外观。
- 近景道具共48,474三角形、14材质批次、约2.06MB，保留同源碰撞；主街样板19处立面精修，没有把全镇414座建筑都宣称为精修完成。
- Forward+ 23张和Compatibility 7张实际相机截图无失败；街道69、连通性14、天气28项通过。新档三夜自动路线85次交互到唯一A结案。自动路线不替代人工试玩。
- SSIL/SDFGI采用同机位小实验评估，未通过收益/观感要求，均未写入默认游戏。当前仍是程序模块和手工道具组合的可玩样板，光照、建筑重复感、近景材质尚有提升空间。
