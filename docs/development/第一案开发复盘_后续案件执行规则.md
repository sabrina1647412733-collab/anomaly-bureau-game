# 第一案开发复盘与后续案件执行规则

依据：第一案的玩家反馈、实际路线排错与`20261023_第一案实机精修验收.md`。这份复盘只更新开发规则，不修改游戏内容，也不表示第一案剩余美术和性能问题已经全部解决。

## 核心教训

第一案把“功能已经接上”“脚本检查通过”和“玩家体验已经完成”混在了一起。场景、剧情、UI、声音不断扩充，真实通行、操作感与统一美术标准却验证得太晚，结果反复返工。后续案件应先完成一个小范围、正常玩家能理解并走完的实机样段，再扩展内容。

## 具体错误及对应规则

| 暴露的问题 | 后续案件的执行方式 | 完成证据 |
|---|---|---|
| 楼体有洞、通虚空、门洞与碰撞错位；交互点藏在玻璃或家具后 | 先锁定比例、门洞、楼梯、边界和可行走白模；用真实玩家胶囊实走，再加材质家具。移动家具后重查被影响路线 | 从入口走到每个必经区域并返回；准星能选中所有必需物件 |
| 修改了模型，但未先确认游戏实际加载哪份资源 | 开始前记录场景入口、运行资源、碰撞来源和当前玩家视角基准图；每轮用同机位复查 | 实机前后对照、明确的资源引用，不用Blender渲染代替游戏效果 |
| 美术精细程度不统一，基础几何加旧纹理仍有廉价感 | 先完成一间主场景及一个近景物件的材质、尺寸、倒角、磨损和灯光样板；其余资产按同标准制作 | 正常光照、近距离和移动观察均成立；记录与参考仍有的差距 |
| 手部与持物姿势不自然；跳蹲动作出现扭曲、朝向问题 | 第一人称独立模型；先定义物件接触点、握法和屏幕占用，再制作姿势/过渡。角色动画验证骨骼静置姿势、坐标轴、蒙皮与脚底接触，不能只按同名骨骼复制变换 | 常用物件逐项实机检查；动画起始、中间、落地/蹲起抽帧及连续播放 |
| 玩家知道目标名称，却不知道为何去、怎么去、到了做什么 | 每个阶段写清动机、当前动作、实际入口、完成反馈；导航经过房门和楼梯，不能隔墙直指终点 | 新玩家不读剧本也能说明当前目的，并通过正常路线执行 |
| 调查以按E读文字、拿文件和等时间为主，剧情增加但玩法未同步增长 | 每个主要线索设计实际操作、可观察结果、与另一证据的关系及复查方式；工作与异常相互推动，控制纯阅读的连续长度 | 至少一条完整“工作→异常→操作调查→核对→反馈”循环，而非只增加文本/按钮数量 |
| 手机、字幕、配音、演出和事件顺序各自推进，出现提前短信、关手机仍说话等问题 | 为事件明确前置条件、进行状态、完成/取消状态；语音、字幕、相机和输入由同一会话控制。关闭、跳过、暂停、读档都要有处理 | 在事件开始、中途、结束分别测试关闭/跳过/暂停/恢复，不出现残留语音或锁住控制 |
| 时间推进可能跨过关键调查，错误操作缺少说明 | 区分时间事件与证据条件；跳时不得替代取证。失败说明具体原因与可执行的复查方向，允许重试，保持既定结局 | 故意选错、拿错、操作反序和晚到，仍能理解并继续主线 |
| UI单独能打开，叠加字幕、持物、手机、演出后却拥挤或越界 | 统一字体、边距、层级、焦点及关闭行为；同时考虑长文本、低分辨率、窗口变化和多界面冲突 | 在目标分辨率及较小窗口操作，不只看静态界面参考图 |
| 分系统测试通过，真实玩家仍被挡住 | 实际发现交接簿在玻璃后、床边休息点被挡、后房退出导航穿墙、检修口接近时坠井；这些说明直接调用接口不足。保留接口测试，同时增加正常按键、中心瞄准、角色物理和新存档连续路线 | 不传送、不注入证据的通关记录；另查错误分支和存读档。测试数量不能证明画面精美或没有其他bug |
| 等到后期才关注性能、兼容模式和导出差异 | 样板阶段即在目标硬件检查帧时间、显存、绘制调用和兼容渲染；导出后检查实际包内资源 | 带硬件、分辨率和场景条件的记录；不能以固定机位数据声称所有电脑稳定运行 |
| C/F路径、旧安装包、历史文档和旧原型测试混用，容易判断错版本 | 保持一个主工程、一个当前进度入口；交付明确源码提交、二进制版本及对应功能。数据和输出按用户要求放F盘。历史测试不能继续假设旧剧情/旧UI | 新电脑不依赖作者绝对路径；玩家打开的版本与说明一致；原资源和回退记录可追溯 |

## 后续案件的制作顺序

1. **先整理第一案遗留项**：明确哪些共用系统已稳定、哪些仍有限制；第二案不能把现有手部、表演和性能问题当作已经解决。
2. **明确剧情与玩法对应关系**：角色动机、关键事实、线索依赖、事件顺序、既定结局和错误后的恢复路径。未经确认的事实保留待查，不能为推动情节擅自补成结论。
3. **用现有工程制作可走白模**：只搭本案必需区域、门洞和连接，先验证入口、返回路线及边界，再布置资产。
4. **完成一段代表性可玩样段**：包含任务动机、实际工作、异常、一次有操作的调查、角色/手机反馈及一次存读档；同时完成主场景和近景物件的实机美术样板。
5. **按样板扩展全案**：每增加一个事件，附带完成、错误、中断和恢复行为；每改一处结构或关键家具，复查相关路线。复用已有手机、背包、时钟、声音和存档接口，避免每案另造一套。
6. **整案验收后交付**：新存档连续正常路线、关键错误尝试、暂停/跳过、存读档、导出包检查。明确区分自动验证、画面复查、人工试玩与尚未验证的范围。

## 报告与承诺

- 分别报告“已经实现”“已经验证”“仍有限制”，不笼统说全部完成、绝无bug或已经达到商业参考品质。
- 视觉目标用Godot同机位实机图判断；声音、操作和引导必须通过实际输入检查。
- 把问题尽早暴露在小样段中解决，不靠后期不断增加提示、特效、道具或测试数量掩盖基础问题。
- 第二案仍在原工程内开发，本文件不授权开始制作第二案，也不要求另建项目。
