## 迭代中发现的问题

- 已修正测试数据目录导致更新缓存错位；更新缓存必须固定跟随EXE。
- 已修正相同内容对应多个路径时误判组需重建，避免未变化的大组多余合并。
- Windows可能短暂保留刚退出的更新器EXE锁；每个plan/download/apply动作改用独立Worker令牌文件名，避免覆写仍被占用的映像。
- 分组激活与固定启动器使用同一个update.lock，防止第二次启动误恢复正在健康确认的更新；健康提交还核对当前清单哈希与目标一致。迁移失败恢复也重新取得此锁。
- 验收驱动读取原子替换的JSON可能短暂得到拒绝访问，或重复运行时读到旧committed记录；已增加短重试并匹配目标清单哈希。原失败日志保留，不把失败尝试写成通过。
- 旧协议重复测试曾遇到文件占用：它正确回滚并启动旧版。该隔离回退子进程不识别新测试退出参数；只清理该确切测试PID，不涉及用户程序。后续旧版验证加入引擎级帧率及退出上限，保证回退也能自然退出。
- 部分导出引擎记录Failed to read the root certificate store；实际GitHub读取、下载、更新均另行验证成功。保留此环境诊断，不宣称所有日志无ERROR。导出扫描还保留历史预览UID重复警告，预览资源不进入Windows包。
